# Strategic Analysis — Principles

Frameworks are thinking tools. Not recipes.

## The Core Principle

**Never force a framework.** The best analyses often emerge from clean thinking about the specific problem — not from applying a standard tool. Use frameworks to structure your thinking, catch what you might have missed, and communicate results clearly. But the thinking comes first.

A Porter Five Forces analysis on a single-supplier market with no threat of substitution is wasted time. A simple "competitive moat" assessment might answer the question in a fraction of the effort.

## How to Choose a Framework

**Step 1:** Understand the core question precisely. What decision does this analysis serve? What will be different as a result of this analysis?

**Step 2:** Identify what type of question this is:
- "How attractive is this market?" → External environment frameworks (Porter, PESTLE)
- "Can we compete here?" → Capability/resource frameworks (Value Chain, RBV)
- "Where do we play?" → Portfolio / growth frameworks (Ansoff, BCG matrix)
- "How do we get there?" → Strategic options frameworks (market entry modes, M&A vs. organic)
- "What needs to change inside?" → Organizational frameworks (7S, TOM)
- "Is this industry about to change?" → Disruption / innovation frameworks (Blue Ocean, platform models)

**Step 3:** Load `references/framework-selector.md` for guidance on which framework fits which question.

**Step 4:** Apply the framework, but adapt it. Ignore dimensions that don't apply. Add dimensions specific to the context.

## Combining Frameworks

Single frameworks rarely tell the full story. Common combinations:

- **Porter + VRIO:** Porter shows industry attractiveness; VRIO shows whether the firm can capture value from that attractive industry
- **Ansoff + BCG:** Ansoff defines the growth vector; BCG positions current portfolio to understand starting point
- **Value Chain + Benchmarking:** Value chain identifies where value is created; benchmarking shows where performance gaps exist
- **Porter + Blue Ocean:** Porter shows current competitive dynamics; Blue Ocean asks whether those dynamics can be restructured

When combining: be explicit about what each framework contributes and what the combined picture shows.

## Avoiding Framework Traps

**The framework becomes the deliverable.** A filled-in Porter template with 15 bullets per factor is not analysis — it's cataloguing. Ask after every framework: "So what? What does this mean for the recommendation?"

**Presenting all factors as equally important.** Every framework has 2-3 factors that actually matter for this specific question. Identify them. Weight the analysis there.

**Using a framework the client doesn't recognize.** PESTLE and Porter are widely understood. Obscure frameworks may be more precise but create communication friction. Match framework sophistication to the audience.

**Applying frameworks to questions they weren't designed for.** Ansoff is for growth strategy, not for operational improvement. 7S is for organizational alignment, not for market sizing.

## First Principles When No Framework Fits

Some questions don't fit a standard framework. That's normal. In those cases:

1. **Define the dimensions of the question** — what factors drive the answer?
2. **Assess each dimension** — what does the evidence show?
3. **Synthesize** — how do the dimensions combine to answer the question?

This produces better output than forcing an ill-fitting framework.
